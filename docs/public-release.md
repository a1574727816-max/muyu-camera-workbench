## 2026-11-02：磁盘满保护修复

运行服务器被其他数据占满后，SQLite WAL 共享文件无法正常建立，已登录请求在会话校验时报磁盘 I/O 错误并返回 500。录像总量仍低于 32 GB，原有应用配额只能限制自身用量，不能保证整个文件系统有可用空间。

释放磁盘后数据库完整性检查为 `ok`，原 TOTP、会话与设备配置保留。修复增加默认 2 GiB 系统空间底线，低空间时优先清理可删除缓存及最旧完成录像；活动文件、引用中文件和其他应用数据受保护。不能回收足够空间时停止录像和回放缓存写入。配置项为 `CAM_DISK_FREE_BYTES`。

SQLite 建连初始化失败时立即关闭句柄；后续存储异常按认证失败关闭原则返回明确的 503 与 `Retry-After`，流式响应遇到认证存储故障会终止，不继续输出受保护媒体。

验证结果：公开代码 72 项 Linux 离线测试通过；保留生产配置的候选代码另有 66 项离线测试通过。新增故障注入覆盖配额以下低空间回收、活动文件保护、录像暂停、缓存中途停止、认证存储失败后恢复和已有视频流终止。真实服务验证使用本地管理员创建的短时诊断会话，完成后撤销，不冒充手机 TOTP 登录验收；两台有声实时预览均实际解码通过，原始录像包含视频/音轨且持续增长，未认证设备 API 仍返回 401。

该保护只管理本项目文件；无法限制其他程序持续写满磁盘，服务器仍需整体容量管理。
